# Pilot Review

Use this after a prospect has agreed to test Cranston on real or representative work. The review should prove workflow value after a skeptical professional checks the output.

Transcript-backed examples: see `marty-brendan-cranston-return-review-exact-quote-bank.md` for a real pilot review that moves into Lacerte export/install, and `scott-sugg-cranston-return-review-incomplete.md` for a review call where Circleback only exposed the first minute of transcript.

## Proof Stages

- Cranston analysis proves package understanding and preparation logic. It does not prove destination integration.
- Output in Cranston's licensed tax environment proves a stronger controlled workflow. It is still not the buyer's installation.
- Live write in the buyer's environment proves values can land in a duplicate or test client inside the buyer's actual software and hosting setup.

## Review What Matters

- Reviewer minutes saved.
- Open items found before review.
- Source traceability for important numbers.
- Unnecessary findings or noisy exceptions.
- Business mappings and trial-balance handling.
- Clean destination-engine output where supported.

## Keep The Pilot Honest

- Use a measured batch only after the first return is useful, such as 25 to 50 returns.
- Include the real operator and reviewer, not only the buyer or owner.
- Compare against a known answer when possible.
- Track what Cranston prepared, what the professional changed, and what blocked export or filing.
- Use approved secure transfer for taxpayer data.
- Do not improvise answers about hosting, subprocessors, retention, training, or data location.
